# Rapport d’intégration SolarVision AI — 14 novembre 2026

L’application existante est connectée à FastAPI. Les huit pages ont été vérifiées dans le navigateur, et les trois modèles ont exécuté de vraies inférences depuis l’interface. Le design Lovable et sa configuration Vite/TanStack sont conservés.

## Panne de connexion résolue

Le backend initial n’ajoutait aucun en-tête CORS. Deux services occupaient aussi différentes interfaces du port 8000 : une ancienne instance Python Windows sur `127.0.0.1`, et Docker sur IPv6. Mettre à jour uniquement le conteneur ne corrigeait donc pas l’instance atteinte par le frontend.

Les origines `http://localhost:8080`, `http://localhost:8081`, `http://127.0.0.1:8080` et `http://127.0.0.1:8081` sont maintenant explicitement autorisées. L’instance native a été redémarrée avec l’environnement CUDA existant et le code corrigé. Le conteneur CPU a été actualisé avec son image en cache et le montage du code, sans reconstruction de PyTorch.

À la fin de l’intervention, le frontend de développement reste sur `http://localhost:8081`, son API configurée est `http://127.0.0.1:8000`, et `/health` y indique `device=cuda`, avec les trois modèles chargés. Le conteneur CPU répond sur `http://[::1]:8000` dans cet environnement Windows. Pour une exploitation durable, choisir un backend ou attribuer des ports distincts.

Les TIFF sont décodés côté serveur ; un aperçu PNG de maximum 1600 pixels est conservé, avec mise à l’échelle des boîtes depuis les coordonnées originales. Les uploads temporaires sont supprimés après traitement. Les anciens enregistrements locaux restent consultables même sans image.

La classification exige `thermal_confirmed=true` et une image thermique compatible PVF-10. Les entrées radiométriques/16 bits sont refusées pour ce modèle, car leur conversion demande une convention scientifique appropriée. L’API ne prétend pas reconnaître automatiquement la provenance thermique d’une image RGB.

## Résultats réels

Les chiffres ci-dessous sont ceux d’images de vérification existantes du projet, pas une nouvelle évaluation statistique. Les durées comprennent l’échauffement éventuel et ne constituent pas un benchmark comparable entre CPU et GPU.

| Exécution | Panneaux | Défauts | Classification PVF-10 |
| --- | --- | --- | --- |
| API CUDA, contrôle HTTP | 15, 910,5 ms modèle | 1, 416,5 ms modèle | classe `0`, confiance 97,77 %, 62,0 ms modèle |
| Docker CPU, contrôle HTTP | 14, 247,9 ms modèle | 1, 115,1 ms modèle | classe `0`, confiance 97,78 %, 47,7 ms modèle |
| Navigateur vers CUDA | 15, 176,6 ms modèle | 1, 143,7 ms modèle | Bottom Dirt, 97,77 %, 43,3 ms modèle |

La légère différence de détection CPU/GPU est conservée telle que renvoyée par les modèles. Aucune prédiction n’a été fabriquée ou corrigée à la main.

La détection de défaut de l’exemple a une confiance d’environ 40 %. Elle est donc masquée au seuil d’affichage initial de 50 %, puis devient visible en abaissant ce seuil, sans nouvelle inférence. L’historique conserve toutes les détections.

Les exports JSON et PNG ont réellement été téléchargés dans le navigateur. La consultation d’un enregistrement sauvegardé affiche son aperçu et sa boîte de défaut. Captures conservées sous `outputs/integration/browser-history.jpg` et `browser-defect.jpg`.

## Limites conservées explicitement

- L’utilisation GPU en pourcentage n’est pas collectée ; la mémoire CUDA est mesurée. Les compteurs de requêtes repartent au redémarrage du processus et ne mesurent pas une disponibilité externe continue.
- La présence de fichiers et d’empreintes DVC ne valide pas le remote ou l’intégrité complète du cache. Les statistiques de datasets proviennent de rapports enregistrés.
- Les runs MLflow viennent de la base locale en lecture seule. Aucun serveur MLflow distant, registre absent ou statut GitHub Actions distant n’est simulé.
- Le workflow GitHub Actions est préparé ; son exécution distante n’a pas été déclenchée, et aucun push n’a été effectué.
- Les scores d’évaluation historiques ne mesurent pas la précision en production. ViT-Tiny reste réservé à la comparaison.
- Les préférences sont locales ; l’API n’ajoute pas d’authentification ou de comptes utilisateurs. Le README décrit son usage local et la persistance des volumes.
- Aucun entraînement, `dvc push`, remplacement de poids, suppression de dataset ou publication de secret n’a été effectué.
